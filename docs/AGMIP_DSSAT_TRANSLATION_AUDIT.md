# AgMIP→DSSAT 변환 규칙과 실제 출력 감사

2026-11-06. 소스 대조와 실제 Java writer 호출을 수행했다. DSSAT 시뮬레이터는 실행하지 않았다. 원본 ACE·CUL·워크북·기본 정책 계약은 변경하지 않았다.

## 고정한 버전과 실행 범위

[공식 변환기 저장소](https://github.com/agmip/translator-dssat)의 현재 소스 `d3f1b89de77ecaac4bd62f5ab427b503f47ef9a8`(2022-01-21)과2015년 말 이전 마지막 소스 `e71ae48b3c35a4d590297ae4df834bc5e442bab5`(2015-06-22)를 보존했다. 후자는 시기상 후보이며 LIRF 패키지를 만든 실제 버전이라는 근거는 없다.

공식 Maven 배포 writer1.2.18과1.2.21을 Java21에서 실제 호출했다. 두 버전은 고정한 공통 의존성을 공유한다. 당시 전체 의존성을 복원한2015년 빌드로 주장하지 않는다. 소스 스냅샷과 배포 JAR의 동일 빌드도 가정하지 않는다.

각 버전에 원본·SLFC1 변경·SLFC1 삭제·입도100배·파종깊이 누락·파종깊이−99·첫 초기NO3 누락·첫DUL 누락의8조건을 실행했다.총16조건의 토양/SOL 및 FileX32개를 보존하고 검사했다. 변형은 진단용 복제본에만 적용했다. 두 writer에는 각각 별도의 깊은 복제를 전달했다.

## 확인한 처리

| 항목 | 두 배포 버전의 실제 결과 | 판정 |
|---|---|---|
| PLDP50 | FileX PLDP5 | writer가mm→cm의÷10 변환 수행.50cm로 해석하면 안 됨 |
| PLDP 키 누락 | −99 출력 | 기존7cm 기본값이 자동 채워진다고 가정하지 않음 |
| PLDP 명시적−99 | −9.9 출력 | 결측 코드도÷10됨.향후 입력 생성 전에 차단해야 함 |
| SLCLY/SLSIL |0.05/0.1 그대로 출력 | 분율처럼 보이는 원본을 자동100배 하지 않음 |
| SLSND | 직접 출력하지 않음 | 원본 sand0.85가그대로 토양 파일에 실린다고 가정하지 않음 |
| SLFC1 | 필드 자체 미출력.수정/삭제해도 두 출력 파일 동일 | 원본 품질 문제는 유지하되, 이 값이 해당 writer를 통해 native에 전달된다는 근거는 없음 |

| 원본 SLPF 미지정 |−99 출력 | 패키지 DOME의0.95가 writer 자체 기본값은 아님 |

원본과 변형 출력의 동일성 비교에서는 생성 시각 주석만 제외했다. 소스 두 스냅샷에서도 PLDP÷10,SLCLY/SLSIL의 직접 포맷,SLFC1/SLSND 미출력을 확인했다.

초기 수분은 파일 폭에 맞춰 반올림됐다. 패키지 원값으로 계산한0–200cm 물337.4mm에 비해 출력 FileX에서 다시 계산하면337.7mm로0.3mm 차이다. 동일 사례의 무기N23.683296kgN/ha는 유지됐다. 이 차이를 모든 입력의 보편적인 허용오차로 쓰지 않는다.

## 이전 감사의 범위 조정

이전 토양 스키마 문제10개는 원본 데이터/현재 사전 대조 결과로 유지한다. 다만 `SLFC1=204836`은 **검사한 writer에서는 사용되지 않는 원본 필드**다. 따라서 이를 직접 native 입력 실패 원인으로 분류하지 않는다. 다른 변환기나 전체 DOME 파이프라인의 사용 여부까지 증명한 것은 아니다.

입도 합1인9개 층은 출력에서 clay/silt가 백분율 열에 그대로 실리는 것을 확인했다. 원본의 분율 의도와 현장 표본 대응은 여전히 미확인이다. 소스·출력 확인을 근거로 자동100배 보정하거나 현장 수량 적합에 사용하지 않는다.

이번 caller는 ACE의 experiment에 soil/weather 객체를 연결하는 명시적 어댑터를 사용했으며 전체ACE/DOME 실행기는 아니다. DOME 채움·날짜 이동·품종 파일 주입·기상 파일 출력·native 초기화는 검증 범위 밖이다. 출력 파일이 존재한다는 사실만으로 바로 실행 가능한 패키지나 농학적 입력이 완성됐다고 표시하지 않는다.

## 계약·근거·후속 작업

기계 판독 계약은 `configs/lirf_translation_contract.json`에 기록했다. 패키지 writer 진단은 허용하되, 자동 현장 입력 생성·농학 검증·본 학습은 계속false다. PLDP 결측/단위 검사 필요 조건을 명시했으며 아직 연결되지 않은 export 단계에서 차단 기능이 실행됐다고 주장하지 않는다.

- 공식 소스2스냅샷: `outputs/runs/20261106T115915Z_agmip_translator_sources_efefb662/verification.json`
- 고정 배포/의존성: `outputs/runs/20261106T120134Z_agmip_probe_runtime_6d681648/verification.json`
- 실제 Java 실행: `outputs/runs/20261106T120239Z_agmip_writer_probe_d5efe8e9/verification.json`
- 출력32파일·소스 규칙 감사: `outputs/runs/20261106T120430Z_agmip_writer_qualification_2ceac4e9/verification.json`

다음은 전체 DOME의 채움·날짜·토양/품종 주입 계약을 확정하고, **현장 타당성과 분리한 공개 패키지 재현용 진단 입력**을 준비하는 것이다. 재현 시에도 원본/가정/변경값을 명시하고 실제 native가 수용한 값과 종료 조건을 검사해야 한다. 현장 품종·입도·관개수N·강수 차이와 외란을 해결하기 전 연구용 실행을 허용하지 않는다.
