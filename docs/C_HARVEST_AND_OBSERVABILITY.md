## 이전 단위 판정 정정

`MZ_GROSUB.for`의 `CumLeafSenes = SLAN / 600. * PLTPOP * 10.`은 이미 kg/ha입니다. 바로 다음 주석에도 kg/ha 환산이 명시돼 있습니다. `CumLfNSenes`는 이 값에 N/건물중 비율을 곱하므로 kg N/ha입니다. 이전에 이를 g/m²로 해석한 판정과 ×10 후보를 철회했습니다. 공식 vendor와 기본 PPO 이미지는 변경하지 않았습니다. 후보 패치 함수/명령은 실행을 거부하고 새 Dockerfile은 후보를 포함하지 않습니다.

이전 `20261106T020048Z_sequence_handoff_7b592b1e`는 수정된 식과의 일치만 확인했습니다. 독립 재고와의 일치를 입증하지 못했으며 검증 근거로 더 이상 사용하지 않습니다. 원본 파일은 보존하고 `configs/evidence_qualifications.json` 및 준비 상태 보고서에서 철회 사유와 대체 근거를 표시합니다.

## 실제 Q/F 재감사

원본 수식·읽기 전용 계측 이미지 `mars-dssat:sequence-native`에서 Q/F × 곡실100/50% × 줄기0/50/100% × 무피해/5회3% 피해, 총24조건을 다시 실행했습니다. 지정 HARVFRAC 일치·건물중 분배·실제 다음 휴경 토양 전달은 통과했습니다.

그러나 STOVN에서 낙엽 N을 빼지 않은 상태로 HRes_Ceres가 CumLfNSenes를 추가하므로 독립 작물 N 재고 대비 `CumLfNSenes × (1−줄기 수확률)`만큼 증가합니다. 줄기를 남기는16조건에서 N 보존 검사는 실패했습니다. 무피해·줄기0% 기준의 초과량은 약1.4136kg N/ha입니다. 이 문제를 코드로 임의 상쇄하지 않고 전체 수지 게이트를 유지합니다. 토양으로 전달된 값이 정확하다는 사실과 그 값의 물리적 보존은 별도 판정입니다.

근거: `outputs/runs/20261106T023809Z_sequence_inventory_reaudit_76087465/verification.json`. 보고서의 `passed`는 전달 검사와 이상 원인 식별 성공을 뜻합니다. `native_n_partition_conservation_verified=false`와 조건별 실패를 함께 확인해야 합니다.

## C 모드의 외부 반출 배분

`harvest_accounting.py`는 실제 보고된 곡실 건물중/N 반출, 부산물 건물중과 외부 N 배분, 잔존 재고를 구분합니다. 낙엽 건물중은 kg/ha로 한 번 포함하고 낙엽 N은 이미 canopy N에 포함되므로 추가하지 않습니다. 부산물 N은 별도 네이티브 반출 측정값이 없어 명시적인 외부 배분으로 표시합니다.

스트레스 조건에서는 `YIELD=GRNWT*10*EARS`와 `GRNWT*PLTPOP*10`이 다릅니다. 실제 수확 보고를 PLTPOP 기준 값으로 대체하지 않습니다. 두 값의 차이도 결과에 기록합니다. 현재 외부 배분 함수의 범위는 곡실 수확률>0이며, 0%는 별도 잠재 수확량 계측 없이 추정하지 않고 거부합니다.

C 모드14조건에서 실제 HWAH/BWAH(출력 반올림 허용범위), 외부 배분 합산, 일별 종자 N·흡수·뿌리 고사·피해 반출을 포함한 식물체 N 재고를 확인했습니다. 관리 시드123456의12조건과 무투입 시드456789의2조건입니다. 후자의 두 조건은 EARS/PLTPOP 재고 차이를 명시적으로 기록합니다.

이 함수는 네이티브 작물/토양 상태를 변경하지 않습니다. C 모드 HARVRES는 여전히0이며 다음 토양 전송을 생성하지 않습니다. 외부 배분의 합산 검사는 수확 후 생태계 수지 검증이 아닙니다.

근거: `outputs/runs/20261106T024226Z_c_harvest_accounting_f64e1770/verification.json`.

재실행: `.\scripts\verify_c_harvest_accounting.ps1`. 소프트웨어 검사는 `scripts/run_tests.py`로 별도 수행합니다.
