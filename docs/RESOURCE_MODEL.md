# 자원·감축·마스크 구현 계약

구현: `src/mars_env/resources.py`
설정: `configs/proposal_v2.yaml`

`ResourceRules.from_config`로 제안서 설정을 읽고
`ResourceLedger.create(rules, beta, shock)`으로 시즌 원장을 생성합니다.
beta는 비용 예산 세 개에만 적용하고 물리적 초기 공급량 200mm는 유지합니다.

하루 처리 순서:

1. `open_day(day, stage)`로 당일 아침 의사결정 원장을 생성합니다.
2. 감축일(파종 후 일수)에 이르면 필요한 감축을 한 번 반영합니다. 단계 기준 보조 분석에서는 단계 최초 진입일과 지연을 확인합니다.
3. `action_masks()`와 정책 관측을 만들고 3차원 행동 인덱스를 선택합니다.
4. `rules.decode(indices)` 후 `ledger.validate(action)`로 실행 전에 검사합니다.
5. 실제 백엔드를 하루 진행합니다. 백엔드 오류 시 해당 에피소드를 폐기합니다.
6. 성공한 전이에만 `next_ledger, cost = ledger.commit(action)`을 채택합니다.

원장은 불변 객체입니다. 새 객체를 반환하므로 잘못된 행동이나 외부 오류에 앞서
예산이 차감되지 않습니다. 같은 원장에는 하루 행동을 한 번만 확정할 수 있습니다.
일자는 시즌 내 단조 증가 정수로 주고, 파종 후 일수 DAP와 혼동하지 않습니다.

물량 감축은 기본적으로 공지 직전 잔량 × (1−감축률)입니다.
보조 계약 `total_entitlement`는 max(0, (1−감축률)×초기 물량−사용량)입니다.
어느 경우에도 사용 이력이나 비용 예산을 소급 변경하지 않습니다.
감축 공지 이후 생육단계가 다시 나타나도 재감축하지 않습니다.

관수 마스크는 물리 잔량과 물 비용 예산을 모두 검사합니다.
질소와 살포는 별도 비용 예산을 검사합니다.
살포는 횟수 상한 없이 예산·최소 7일·istage<5를 함께 검사하며 최초 살포에는 간격을 적용하지 않습니다.
마스크 순서는 관수 6개, 질소 9개, 살포 2개이며 True가 실행 허용입니다.
무투입은 항상 허용합니다. 부적합 행동은 자르거나 다른 행동으로 바꾸지 않고 거부합니다.

관수·질소 작업비는 관리 수익용 `Cost.total`에 포함하지만 자원 구매 예산에서는 제외합니다.
방제 비용 50USD에는 작업비가 이미 포함되어 있습니다.
원장은 매출을 지급하지 않습니다. 종료 구분·수확 매출·보상은 후속 모듈에서 처리합니다.

원장에는 미공지 감축 시나리오가 들어 있습니다. 객체 전체를 정책 관측으로 전달하면 안 됩니다.
감축 공개 정보는 `announcement()`를 사용합니다. 공지 전 비율은 0이며 공지 여부를 별도 표시합니다.

이 모듈은 실제 DSSAT와 아직 연결되지 않았습니다. 일별 공지·조사 순서는 이후 환경 래퍼에서 묶습니다.
본 검사에서 사용한 허용 오차는 금액·잔량 비교의 부동소수점 오차용 1e-8입니다.
