# 동일 이미지 CPU·CUDA 처리량 비교 준비

과거 장기 실행은 각각 102,400단계와 PPO 갱신 800회를 완료했다. CPU 74.35단계/초와 CUDA 94.72단계/초는 별도 안정성 근거다. 체크포인트의 γ, λ, 배치, 롤아웃 길이, 에폭, 환경 수, 시드와 학습률은 같았다. 이미지와 벤치마크 소스 해시는 달랐고 설정 스냅샷은 상태·검증 항목에서 차이가 있었다. CPU 실행에는 이미지 빌드·진단이 겹쳤고, 분포 인자 검사의 CLI 상태도 CPU 보고서에 기록되지 않았다. 두 장기 수치로 장치 차이를 추정하지 않았다.

## 동일 이미지 예비 실행

RTX 3060 Ti가 노출된 하나의 메타데이터 보정 CUDA 이미지에서 CPU→CUDA→CUDA→CPU 순으로 실행했다. 분포 인자 검사를 켜고 4환경·1,024단계를 사용했다. 설정·소스·이미지, PPO 설정, 초기 시즌 주소 0–3을 확인했다. 동일 시즌 주소와 정책 시드는 기기 간 이후 행동이 항상 동일함을 뜻하지 않는다.

| 순서 | 장치 | 처리량 (단계/초) | 초기화 / 학습 / 평가 (초) | 최대 표본 RSS (MiB) |
|---:|---|---:|---|---:|
| 1 | CPU | 180.07 | 3.47 / 5.69 / 2.59 | 2,560.55 |
| 2 | CUDA | 121.54 | 3.43 / 8.43 / 4.34 | 3,157.50 |
| 3 | CUDA | 138.78 | 3.05 / 7.38 / 4.21 | 3,158.05 |
| 4 | CPU | 196.24 | 3.46 / 5.22 / 2.80 | 2,563.46 |

처리량은 PPO 갱신을 포함한 학습 시간으로 계산했다. 초기화, 체크포인트, 평가는 따로 측정했다. CUDA에서는 학습 구간 양 끝에서 동기화했다. RSS는 학습 프로세스 트리의 표본 합이며 GPU 메모리와 분리했다. PyTorch 학습자 최대 CUDA 할당량은 두 번 모두 약 25.38 MiB였으며, CUDA 전체 장치 메모리나 드라이버 메모리를 포함하지 않는다. 장치 전체 GPU 사용량은 각 실행 직전·직후 스냅샷에 따로 기록했다.

두 쌍의 CPU/CUDA 처리량 비율은 1.482와 1.414였다. 네 실행 모두 PPO 갱신 8회와 학습 시즌 4회를 완료했다. 무효 행동, 백엔드 오류, 시간제한 종료는 각각 0건이었고 시뮬레이터 워커 정리를 확인했다. 실행 직전 GPU 사용률은 2–12%였다. 호스트 외부 부하의 완전한 통제와 장시간 열·전력 변화는 짧은 실행으로 확인할 수 없다.

## 장기 실행 절차

`scripts/benchmark_controlled_devices.ps1 -Steps 102400`으로 같은 교차 순서의 장기 기술 비교를 실행할 수 있다. 현재 실행기는 시작 시 다른 컨테이너 작업이 있으면 중단하며 각 장치 실험을 순차 실행한다. 장기 결과에서 두 쌍의 비율, 각 반복의 초기화·평가, 메모리와 오류 건수를 함께 검토한다. 이번 예비 결과는 본 학습 장치 확정의 근거로 사용하지 않았다. 농학 검증과 본 학습은 보류 중이다.

과거 감사와 예비 실행의 근거는 `outputs/runs/20261107T043123Z_controlled_device_pair_8a6d1978`에 있다.
