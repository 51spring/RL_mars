# LIRF DOME 실행과 진단 입력 경계

2026-11-06. 공식 DOME1.4.15와 writer1.2.21을 실제 Java21에서 실행했다. 이 문서의 판정은 진단용 입력 준비에 한정한다. DSSAT native 실행과 현장 검증은 수행하지 않았다.

## 실제 적용한 원본 규칙

원본의7개FILL을 규칙 경로와 생성기 경로 양쪽에서 실행했다. 생성기 정의의 마지막 빈 객체는 새 처리 조건으로 세지 않았다. 다음 값이 두 경로에서 같았다.

| 변수 | 결과 | 근거 |
|---|---|---|
| SLDR / SLRO |0.5 /60| 패키지의 채움 가정 |
| SLPF / SALB |0.95 /0.13| 패키지의 채움 가정 |
| FEDEP |모든 시비 이벤트5| 패키지의 채움 가정 |
| SDAT |20080412| 파종20080512−30일 |
| ENDAT |20081128| 기존 값 보존. 삭제한 별도 대조에서도 파종+200일로 같은 날짜 생성 |

기존 SDAT20080101·SLPF0.77·첫 시비 깊이9를 넣은 대조에서는 FILL이 이 값들을 보존했다. 실제4개DOME 조건으로 두 날짜 함수의 지원과 기존값 보존을 확인했다. 이 채움 값을 현장 실측값으로 표시하지 않는다.

원본 linkage의 실험명은 `COGreeleyLirf`, ACE는 `COGreeleyLirf_1`로 정확히 같지 않다. DOME 이름은 대소문자를 제외하면 일치한다. 이번 진단은 패키지에 있는 단일 DOME을 명시적으로 선택했다. 자동 linkage 해석이나 당시 전체 파이프라인 재현을 완료한 것으로 처리하지 않는다.

## 내보내기 경계 구현

`src/mars_env/lirf_export_guard.py`의 `require_export`를 실제 writer 호출 직전에 연결했다. 실패 시 예외를 발생시키므로 Python 최적화 옵션으로도 해제되지 않는다. 허용 목적은 `package_diagnostic`뿐이며 현장 검증 목적은 거부한다.

검사 항목은 단위 선언, 파종 깊이 결측/−99/비정상 수치, soil/weather 식별자, 품종 계수 행, 입도 합100%, 토양·초기조건 층 순서/범위와 수분·N, 겹치는 층의 포화수분 초과, 시비N/깊이, 날짜 순서와 일별 기상 연속성/최저·최고기온 순서다. 입력을 고치거나 생략된 값을 기본값으로 채우지 않는다. 검사한 writer에서 쓰지 않는 SLFC1은 원본 품질 경고로 보존한다.

원본 입도는9개 층 모두 합1이므로 writer 호출 전에 차단했다. 이어서 복제본의 입도27값을 명시적으로100배 한 **통합검사 전용 fixture**를 만들었다. 변경 전후 값과 목적을 `diagnostic_assumptions.json`에 기록했다. 이 변경은 현장 단위의 확정이나 자동 보정 허용을 의미하지 않는다.

12개 음성 대조(파종 깊이 누락/−99/NaN, 알 수 없는 단위, NO3 누락/−99, DUL 누락, 입도 불일치, 품종 행 누락, soil/weather 연결 불일치, 현장 검증 목적)가 실행 가능한 경계에서 거부됐다. 이 입력에는 writer를 호출하지 않았다.

## 준비한 파일과 확인 범위

검사한 fixture만 실제 writer에 넘겼다. 결과 폴더의 SOL/FileX/WTH와 원본 그대로 복사한MZCER045.CUL, 총4파일을 보존했다.366개 기상일(2008001–2008366), 출력 파종 깊이5cm, 표면SLPF0.95/SLDR0.5/SLRO60, 모든 시비 깊이5, simulation start08103(4/12), 첫층 clay5%를 독립적으로 읽어 확인했다.

초기상태는1/1인데 시뮬레이션 시작은4/12다. 현재 파일은 원본/규칙을 진단 목적으로 유지한 것이며 native가 초기상태를 어느 날에 어떻게 수용하는지는 아직 검증하지 않았다. 계수 파일045/실행기048 호환성, 품종 생리계수의 독립성, 토양 입도·관개수N·강수/관수 일정과 현장 외란도 남아 있다. **native_ready=False, research_ready=False, main_training_allowed=False**를 유지한다.
